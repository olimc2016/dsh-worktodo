这页只是 mockup：不改应用代码，也不读写任何数据。四个方案用同一组示例数据， 分别在窄 320 / 中 420 / 宽 600 的面板宽度下各渲染一遍；每格都含普通行、空白行（hover 才显出「＋日期」「＋项目」）、 长标题、hover 态、已完成态，以及高/中/低三档旗子。行尾的铅笔/删除与真实面板一致。

A static mockup comparing four layouts for a task row in the dsh-worktodo panel — no app code is touched. Every scheme renders the same sample rows at 320 / 420 / 600 px panel widths, covering normal, empty, long-title, hover, done and all three priority flags. Hover any row for the real interaction; rows marked “hover” show it forced.

推荐 B 的骨架 + C 的窄屏自适应：宽面板永远单行、小字钉在行末；窄到标题被挤时，小字自己落到第二行并与标题左对齐。同一份结构，两种宽度表现。 Recommended: B's single-line skeleton, with C's narrow-width fallback.
